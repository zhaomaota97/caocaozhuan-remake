# EEX opcode 32：头像状态写入

## 原生链与精确语义

原生分派器 `0x4109EF` 的 case 0x20 调用 `0x416FD8`。处理器使用 `0x4183F7` 读取 tag 74 的 16 位值，通过 `0x409540` 读取公共记录 `0x4B0770+0x11`，再通过 `0x418D40` 写回同一字节。

设旧状态为 `old`，完整参数为 `value`：

```text
tag 不等于 74：返回 5，不改状态，只消费 opcode 和 tag（4 字节）
value 等于 0x8000：返回 5，不改状态，消费 6 字节
value 的低字节等于 0xFF：new = old & 0xE0，返回 1
其他：new = (old & 0xF0) | (value & 0xFF)，返回 1
```

最后两种情况消费 6 字节。普通写入不是只取低四位；参数高半字节中置位的位也会 OR 入状态。255 分支清除低五位，因此同时清除了低四位表情和 bit4，而保留 bit5–7。65535、511 等低字节为 255 的值也走此分支。

`0x8000` 既是读取器错误哨兵，也会令 tag 正确、实际参数恰好为该值的指令返回 5。不能把该值当作正常表情号处理。这里尚未把返回 5 的上层调度后果解释成具体 UI 错误行为。

## 与头像选择关联

`0x4075A7` 直接读取上述状态。低四位影响角色身份 0 的八种头像，并令身份 1 在低四位为 4 时使用头像 224；bit7 参与身份 1 的其他选择；bit4、bit5、bit6 分别参与身份 35、8、4 的特殊头像选择。phase 来自公共记录 +6，未由本指令修改。

因此脚本中应保留这个公共状态，而不是把每条指令解释成只修改当前说话角色的图片。完整选择表及资源信息见 `portrait-loading-readable.md`。
