# AI 多目标评分汇总

原生函数 `0x438D96(list,baseScore,category,actorSlot,effectId)`，由特殊范围普通攻击及策略评分路径调用。列表以FF结束，条目为战斗槽位。

## 汇总规则

空列表：基础分<5时变0，否则减4。非空列表：保留基础分，按每个条目贡献累加。最后结果最小0；本函数没有255上限。上层如何截断需要分别按调用点处理。

| category | 每个目标的贡献 |
|---|---|
| 0，effectId=FF | 预计普通伤害>=当前HP加10；否则 `floor(伤害*10/最大HP)` 非零加4；否则0 |
| 0，effectId非FF | `0x4390EF` 判断适用后加3；若目标槽等于攻击者槽记录+8的值，改为加6 |
| 1 | 适用且 `floor(当前HP*100/最大HP)` <60，加5 |
| 2 | 适用且目标槽记录+0x18字节<4，加3 |
| 3 | 适用且目标槽记录+0x19字节<4，加3 |
| 4 | 与类别3一样读取+0x19，适用且值<4加3 |
| 5 | 适用且目标槽记录+0x1E字节非零，加3 |
| 其他 | 无贡献 |

类别3和4确实在当前伪代码中使用相同读取器，探针也保留真实读取器验证此行为；不能因为名称推测而擅自改成另一个字段。字段对应的具体状态业务含义仍需与策略表、状态写入函数和实际场景联合确认。

类别0、effectId=FF的普通范围伤害路径不会调用适用性检查器。其他列出的收益路径先经 `0x4390EF(actorSlot,targetSlot,effectId)`；本轮只控制该检查器的返回值，未声称恢复其全部前置条件。

列表不去重，同一槽位重复出现就重复贡献分数。调用者生成列表时是否可能产生重复，需要独立验证；不能把合成重复输入的行为说成实际游戏一定会重复计分。

## 与普通攻击的连接

`0x438A20` 的非零特殊范围分支调用 `0x435AAD` 生成列表，再以 category0、effectIdFF 调用本函数。它用多目标汇总结果替换原分数，随后仍会进入目标反击覆盖的减1判断。

因此多目标收益是追加在基础评分上的贡献，并非逐目标再套一次完整的单目标80分/16分规则。空列表扣4也是在此函数中发生，而不是直接认为“没有额外目标就维持原分”。
