# AI 攻击候选生成、过滤与选择

## 原生调用链

`0x438965` 先用 `0x43F8BE` 取得攻击范围编号，再调用 `0x436586(actor,candidateXY,shape,0x80,0)` 生成候选列表 `0x4AC748`。随后逐候选调用 `0x438A20`，将获胜目标写入 `0x4B2C30`。

`0x436586` 通过几何函数枚举格子，统一交给 `0x437A04` 处理。

## 候选过滤

`0x437A04` 在候选收集模式下：

1. 检查坐标是否在地图宽高范围内。负坐标传入字节参数后会回绕成大值，因而被边界检查排除。
2. 用 `0x435884` 查询该格占用槽位，无有效单位时跳过。
3. 将调用者传来的槽号与目标槽号分别交给 `0x406710`，比较槽记录 `+4 < 35` 的结果。
4. flag bit0=0时只收集二分结果不同者；bit0=1时只收集相同者。
5. 目标当前HP必须非零。符合者追加到列表，不在此排序。

AI攻击入口使用flag=0x80，因此只收集二分结果不同、HP非零的目标。0x80也避免该函数把绘制/标记用数据写进地图缓冲区。上一轮评分函数中的“同阵营仍可能因标志加分”并不代表完整调用链会选择友方，候选过滤在评分之前发生。

这里的二分不等于精确的阵营字节相等判断，不能直接替换成 `factionA !== factionB`。

## 枚举与最终选择

shape0的正交相邻格遍历顺序来自原版常量表 `0x48DF68`：上 `(0,-1)`、右 `(1,0)`、下 `(0,1)`、左 `(-1,0)`。shape1先枚举相同正交格，再枚举另一张表中的四个对角格。

`0x438965` 初始最高分为0、目标FF。每次只使用评分返回值的低字节，并且只有严格大于当前最高分才更新。因此：

- 相同最高分保留先枚举的目标。
- 全部目标零分时目标保持FF。
- 评分返回256的比较值是0，511是255；不能把返回值高位也拿来排序。
- 扫描遇到FF终止，遇到大于114的槽位也停止，不会跳过坏项继续扫描。这一项当前来自静态函数证据，未加入本轮动态损坏列表探针。

## 剩余验证范围

本轮单位只放在四个正交邻格，shape1的对角候选实际为空；不能据此宣称对角目标、全部范围形状或地图中所有特殊上下文已验证。槽位使用1–4，阵营字段取0/35代表二分两侧；其他值和目标列表损坏边界尚需单独探针。完整AI仍需接通真实攻击评分、策略评分、候选移动格生成与实际行动执行。
