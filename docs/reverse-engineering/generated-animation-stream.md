# Runtime-Generated Animation Movement Streams

`python tools/verify_generated_animation_stream.py` passes 30/30 native
cases. The earlier plan to identify a source animation file does not apply
to every command stream: `0x42869C` synthesizes movement commands in memory.

Native `0x4284C5` finds the first clear bit in allocation mask `0x498070`.
There are 32 slots; each maps to a 1KB area in buffer view `0x4AE4C8`.
The generator writes slot ID to object+0x3C and slot*1024 to object+0x3E.
If all bits are allocated, it returns low word 0xFFFF without changing the
object's slot/offset or consulting the path selector.

The generator repeatedly obtains a direction from `0x42836E`, writes its
low byte and advances working coordinates using original `0x4281C7`.
When the selector returns 0xFFFF:

- If end direction is -1, a nonzero trim argument removes up to the entire
  generated path from its end before termination.
- Otherwise append `endDirection | 0x10`, ignoring trim.
- Write 0xEF at the resulting end of stream.

The matrix tests masks 0/1/3/0x7FFFFFFF/0xFFFFFFFF, end direction -1/2 and
trim 0/1/10. A controlled selector emits north, east, end. Allocation,
32-slot limits, native coordinate stepping, buffer access, byte writing and
termination execute as original code. Only the path selector is replaced;
this test does not establish its pathfinding algorithm. Generated bytes and
mask changes are compared against an independent expected encoder.

The native success return has unspecified/derived register bits and is not
used as the allocation ID; the allocation-failure low word is checked.
The authoritative slot/offset are object fields. Raw evidence:
`native-generated-animation-stream.json`.

Together with the native command-runner verification, this identifies the
producer/consumer link for synthesized scene-object movement. Asset frame
images and other command-stream producers may still come from files and
require separate tracing.
