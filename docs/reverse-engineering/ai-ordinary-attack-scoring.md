# AI 普通攻击目标评分

函数：`0x438A20(actor,targetSlot,packedCandidateXY)`。这是候选目标的评分函数，不是完整 AI，也不是最终伤害结算。

## 读取字段

- 目标槽记录为 `0x4B2C50 + targetSlot*0x24`，首个32位值是角色记录索引，角色记录为 `0x4A1B68 + index*0x48`。
- `0x406710` 返回槽记录 `+4 < 35`。函数用该二分结果比较双方，而不是直接比较阵营字节是否相等。
- 目标当前 HP 为槽记录 `+0x10` 的32位值；最大 HP 经 `0x40721B` 获取。
- 基础预计伤害来自 `0x43BC4B(actor,targetCharacter,0,0)`。

## 非溅射评分规则

先取零分。有效目标槽范围为0–114，在双方 `+4 < 35` 结果不同时计算基础分：

| 条件（按先后顺序） | 基础分 |
|---|---:|
| 预计伤害 >= 当前HP | 80 |
| `floor(预计伤害*10/最大HP)` 非零 | 16 |
| `floor(当前HP*100/最大HP)` < 41 | 16 |
| 其他，攻击者模式字节 +0x0E 等于1 | 10 |
| 其他 | 2 |

随后执行这些调整：

1. 目标槽 `+0x1E` 的 bit3 置位，加8。该位完整业务命名仍待关联，不擅自叫某种异常状态。
2. 当前评分非零且目标角色记录索引<174时：若该索引等于全局 `word(0x492F90+0x3D06)`，或目标槽恰好为35，加8；否则加4。此处全局角色身份的完整业务含义仍待证实。
3. 若评分<75，并且 `0x43FFED(actor)` 返回非零，将分数置零，后续处理跳过。静态看该函数在兵种编号8、9、10、11、18、19、20时返回1，兵种读取和映射仍需联合验证。
4. 若攻击者具有 `0x407818` 返回的特殊范围/攻击类型，则进入 `0x435AAD → 0x438D96` 的多目标评分链。多目标汇总器已另行完成4200组受控原生验证，见 `ai-multi-target-scoring.md`；范围生成和该分支联合调用尚未验证，不能用普通分数替代。
5. 当前评分非零时生成目标的攻击覆盖图；若候选移动格对应字节为1且分数>1，减1。它不是直接按距离扣分。

反击覆盖查询使用传入的候选格，而目标攻击范围的起点来自目标槽记录坐标，二者不可混用。

## 重要边界

同阵营合成输入仍可能因目标bit3得到分数，因为加8发生在双方基础分判定之外。这是该函数的真实局部行为，不代表原版AI会攻击自己人：调用者候选链现已补充6144组受控原生验证，确认评分前过滤同侧及零HP单位，见 `ai-candidate-filter-and-selection.md`。全部范围与上下文仍未覆盖。

最大HP固定100避免将未知属性初始化混入本次探针。测试尚未覆盖零最大HP、整数乘法溢出、无效槽位、全部兵种实际过滤链、特殊范围、真实伤害函数与评分联合调用，以及完整回合动态轨迹。这些仍是后续逆向任务。
