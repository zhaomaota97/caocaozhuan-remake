# EEX 指令语义覆盖状态

当前 `analysis/eex/opcode-index.csv` 记录了 108 个操作码，106 个有明确的原生分发处理器。参数读取标签来自 `0x4109ef` 分发器调用的统一参数读取函数，是静态证据，不等同于完整语义。

按当前静态证据分组：71 个操作码有参数读取调用，14 个观察到字符串参数读取，21 个有处理器但没有参数读取调用，2 个是保留/终止值。后 21 个已完成初步静态分类，但仍优先作为动态验证对象，因为它们更可能是无参数控制、状态切换或直接副作用指令。

这组低频指令已完成初步静态语义命名：

* 操作码 `3` -> `0x4112DF`，无参数并固定返回 `6`，表现为解释器控制状态码；
* 操作码 `7` -> `0x415C46`，读取并清除全局 `0x4AE4C0`，表现为一次性事件/标志消费；
* 操作码 `10` -> `0x415AD7`，把 256 项表通过 `0x4184D1` 全部清零后返回 `1`；
* 操作码 `12` -> `0x4143A4`，无参数并固定返回 `8`，同样属于解释器控制状态码。
* 操作码 `13` -> `0x4143AE`，调用 `0x42C858(0)` 后返回 `7`；
* 操作码 `14` -> `0x415890`，若 `0x40B922` 条件成立则调用 `0x455FFD(3)`，随后返回 `1`；
* 操作码 `16` -> `0x41590D`，调用 `0x433359` 后返回 `1`；
* 操作码 `28` -> `0x413EBD`，根据 `0x40B913` 的模式选择 `0x428B11` 或 `0x1E405`，随后返回 `1`；
* 操作码 `29` -> `0x413EE2`，调用 `0x1E5C2` 后返回 `1`；
* 操作码 `30` -> `0x413EF1`，无参数并固定返回 `2`。
* 操作码 `47` -> `0x413652`，调用 `0x426BD5` 后返回 `1`；
* 操作码 `66` -> `0x411D63`，刷新全局配置 `0x4B3D08`，读取脚本槽 5 并判断是否为 `1`；
* 操作码 `67` -> `0x411D8E`，刷新同一配置，读取脚本槽 6 并判断是否为 `1`；
* 操作码 `68` -> `0x412230`，清零 256 项表，重置 0x73 个记录，再按 `0x48B350` 的初始表恢复记录 ID。
* 操作码 `73` -> `0x415795`，条件成立时调用 `0x455FFD(2)`；
* 操作码 `81` -> `0x41626A`，遍历 0x73 个武将记录，对状态类 `2` 的记录清除标志、重置计时并重算属性，然后刷新战场配置；
* 操作码 `84` -> `0x415771`，条件成立时调用 `0x4CC03`；
* 操作码 `90` -> `0x416C97`，调用 `0x4BAC2`；
* 操作码 `95` -> `0x4175E8`，初始化全局表 `0x4B3C80`；
* 操作码 `97` -> `0x4176A8`，从全局表 `0x4B3C80` 执行另一种表处理；
* 操作码 `106` -> `0x416DFA`，条件成立时清零全局标志 `0x4B3D10`。

已完成的证据层：

新增动态验证：`python tools/verify_eex_low_frequency_native.py` 对低频操作码 3、7、10、12、13、30 全部通过；原始结果见 `analysis/native-eex-low-frequency-validation.json`。这补充了操作码 10 的 256 项清零、操作码 7 的全局标志消费、操作码 13 的全局刷新调用，以及三个固定解释器控制返回值的原生证据。

* 117 个 EEX 文件、469 个段均已定位；
* 2320 个候选分支均已按原生游标规则切分；
* 2320 个分支体均可结构化解码并重新编码为字节级一致；
* 剧情文本已提取为 9420 个 CP936 可读字段；
* 分支选择、单位计数、动画命令、单位恢复、数值谓词、公共配置和敌方设置已有原生验证。

尚未完成的语义层：

* 多段脚本之间的跳转、循环和条件状态机；
* 触发战斗、奖励、死亡/撤退和地图切换的完整流程；
* 对所有 2320 个分支逐条建立“输入状态 -> 原生副作用 -> 输出状态”的动态样本。
