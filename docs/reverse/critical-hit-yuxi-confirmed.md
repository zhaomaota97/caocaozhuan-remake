# 玉玺与会心一击

现在已经找到静态代码中的直接证据，能够确认玉玺的必暴效果路径。

## 物品数据

`analysis/items.csv` 中玉玺为：

```text
id = 82
category_byte = 0x41
category_group = 2（辅助）
```

## 被动效果判定

`0x41C4E9(item_id, actor_id, param_3)` 根据物品类别选择武将被动标志：

* 类别 `0x41`：要求武将标志 `0x08`；
* 类别 `0x42`：要求标志 `0x10`；
* 类别 `0x43`：要求标志 `0x02`；
* 类别 `0x44`：要求标志 `0x04`。

类别 `0x41` 因而正好对应一类“装备后检查标志 0x08”的特殊被动。玉玺的物品类别就是 `0x41`，不是普通属性加成物品。

## 会心概率写回

在 `0x4404BD` 的动作处理分支中，原生代码调用：

```c
iVar6 = FUN_0041c4e9(item_id, actor_id, 1);
local_8 = -(uint)(iVar6 != 0) & 100;
```

也就是：

```text
critical_probability = has_category_0x41_passive ? 100 : 0
```

这条路径已经证明了玉玺装备后会把该动作的会心概率设为 100%。相关原始证据：

* `analysis/native-main/pseudocode/0041c4e9.c`
* `analysis/native-main/pseudocode/004404bd.c`
* `analysis/items.csv` 的 ID 82 记录

## 动画

`0x4404BD` 随后进入效果/动作绘制分支；会心概率不是单纯伤害倍率，而是动作结果参数。函数在计算结果后调用 `0x450ED5`/`0x45119F` 绘制两侧的生命/资源条，并通过 `0x451913` 绘制固定的 24×24 UI/结果图块。攻击者和目标的主体动画由调用者 `0x441488`、`0x4541A9` 选择；会心专用帧/特效资源的最终编号仍需要一次装备玉玺与未装备的动态画面捕获才能逐帧对应。

可复现检查：`tools/verify_yuxi_critical_static.py` 会验证玉玺 ID/类别、`0x41` 对 `0x08` 标志的检查、攻击路径调用和 100 概率写入，共 5 项静态断言。

当前没有把某个 `Mcall` 文件直接标记为“会心动画”：`Mcall00..08` 的时间线只记录帧、调色和音效索引，原生调用还需要结合运行时动作参数才能建立一一对应关系。

另外，`0x43FC48` 只根据武将动画类别和记录中的动作子类型选择 `Unit_atk`/移动/特殊动画 bank（类别小于 `0x22` 时按三组攻击 bank 计算，其他类别使用扩展编号），没有读取会心概率字段。因此会心专用视觉效果应在 `0x4404BD` 的结果/特效调用链中，而不是基础单位 sprite 选择器中。
